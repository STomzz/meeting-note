# 问答（检索增强 + 流式）

问答页把「本地检索」和「对话模型」串起来：**先在本机找回片段，再把片段拼进提示词**，
模型只负责组织语言。检索不联网；只有命中的片段会发给对话模型。

## 一次问答的流程

| 步骤 | 说明 |
| --- | --- |
| 1. 检索 | 全文（FTS5 trigram）＋ 可选向量召回，RRF 融合；可选重排；可选图谱邻居扩展（见 `docs/graph.md`） |
| 2. 组装提示词 | 片段带 `[编号] 《标题》（路径 第 x-y 行）`，系统提示词要求「只依据片段回答 + 用 [编号] 标注来源」 |
| 3. 流式生成 | `POST /chat/completions`（`stream: true`），Rust 侧解析 SSE，经 Tauri Channel 逐字推给前端 |
| 4. 收尾 | 返回完整答案（耗时、tokens、来源列表），写入会话历史 |

检索为空时**不调用模型**，直接给出兜底文案（省配额、避免瞎编）。

## 流式与停止

- 前端调 `ask_question_stream`，Tauri 用 `Channel<QaEvent>` 推送三类事件：
  `retrieved`（来源 + 检索轨迹）→ `delta`（正文增量，另有 `reasoning` 思考增量）→ `done`（完整答案）。
- 「停止生成」调 `qa_cancel`，Rust 侧 `AtomicBool` 在下一次增量检查时中止读取；
  **已生成的部分会保留**并在回答下方标注「已停止生成」。
- 生成中不显示复制/导出等操作（避免复制到半截内容），检索过程行也在结束后才出现。

## 引用怎么用

- 回答里的 `[1] [2]` 渲染成**可点角标**：悬停显示「标题 · 第 x-y 行」，点击跳转到笔记并**高亮对应行**。
- 角标编号对应回答下方的「引用来源」列表；列表行点击同样是「打开并定位」。
- 模型多标的编号（没有对应来源）保持原样，不会误导点击。

## 会话历史

| 项目 | 说明 |
| --- | --- |
| 位置 | `<应用数据>/chat-history.json`（Windows 为 `%APPDATA%\com.bnu.notes\`；Android 为应用私有目录） |
| 格式 | `{ "version": 1, "conversations": [...] }`，结构由前端定义（Rust 只做原子读写） |
| 内容 | 问题、回答、来源片段（正文截断到 400 字符，够回看与定位）、模型与耗时 |
| 上限 | 最多 60 个会话（置顶的不淘汰），空会话自动丢弃 |
| 操作 | 左栏按 置顶 / 今天 / 昨天 / 7 天内 / 更早 分组；hover 有 重命名 / 置顶 / 删除；**双击会话名**可就地改名 |
| 备份 | 与其它数据一样只在本机；浏览器预览模式存 localStorage（键名 `bnu-notes-chat-history`） |

## 追问建议

点回答工具栏的「猜你想问」会**按需**调用一次对话模型（≤200 tokens），返回最多 3 条中文追问；
点击即在同一个会话里继续提问。

> 上游网关限流约 **9 请求/分钟**（转写、图谱抽取、追问共用）：短时间内连续追问 + 点「猜你想问」
> 可能触发 429，等十几秒再点即可。

## 排障

| 现象 | 处理 |
| --- | --- |
| 提示未配置对话模型 | 设置 → 模型配置 → 对话，填 baseURL + Key + 模型名 |
| 回答为空 / 提示思考被截断 | 上游若默认开启思考，可能吃满 `max_tokens`：在对话端点的 `params` 里加 `chat_template_kwargs.enable_thinking = false` |
| 429 | 等十几秒再点；或减少同时进行的转写 / 图谱抽取 |
| 引用点不到行 | 目标笔记被重命名/删除，或行号落到了文件末尾；重跑一次扫描/抽取即可刷新 |
| 历史没保存 | 桌面端检查 `<应用数据>/chat-history.json` 是否可写；预览模式检查浏览器是否禁用了 localStorage |
