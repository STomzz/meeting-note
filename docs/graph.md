# 知识图谱（P4）

从笔记里抽出**实体**与**关系**，存在本机 SQLite 里；图谱页用力导图交互，
问答时用「邻居扩展」把相关片段补进召回。抽取全部在客户端发起，云端只用到对话模型。

## 数据在哪里

| 内容 | 位置 |
| --- | --- |
| 实体 / 关系明细 / 块-实体 / 抽取账本 | `<应用数据目录>/index.sqlite`（表 `entities` / `relations` / `chunk_entities` / `graph_state`） |
| 图的可视化与筛选 | 纯前端（G6 力导图），不落盘任何坐标 |

设计取舍：

- `relations` **按「一次出现一行」存明细**（带 `note_id` / `chunk_id` / `evidence`），
  聚合强度（出现次数）在查询时算。好处是：重建某篇笔记 = 先按 `note_id` 删除再插入，
  **天然幂等**，并且每条边都能回溯到具体片段与句子。
- 实体是**全局共享**的（`UNIQUE(name, kind)`），所以「李娜」在周会与部署记录里是同一个节点，
  跨笔记的关联天然连起来。
- 笔记内容变了 → 重新索引时**主动清掉该笔记的图谱数据**（块 id 会变，旧关系与溯源必须一起清），
  下次抽取重建，不会留下指向旧块的关系。

## 怎么触发抽取（手动 + 增量）

| 入口 | 行为 |
| --- | --- |
| 图谱页「增量抽取」 | 遍历所有笔记，**只处理没抽过或改动过的**；可随时「中断」（当前批次结束后停） |
| 图谱页「全量重抽」 | 忽略内容哈希，全部重抽（换对话模型后建议做一次） |
| 图谱页出处笔记行的「重抽」 | 只重抽这一篇 |
| 命令层 `graph_extract_note` | 单篇抽取（`force = true` 忽略哈希） |

增量靠账本 `graph_state.content_hash`（标题 + 全部块文本的 FNV-1a 哈希）：

- 哈希一致 → 直接跳过，**零请求**；
- 有批次失败 → 账本记 `error`、**不写哈希** → 下次自动重试；
- 单篇失败不阻断整轮，错误汇总后显示在图谱页横幅里。

进度走 Tauri 事件 `graph-progress`（`notesDone / notesSkipped / notesFailed / batchesDone /
currentTitle / message`），完成后另发 `graph-extracted`。

## 抽取怎么防瞎编

| 约束 | 说明 |
| --- | --- |
| 实体名必须是**原文子串** | 归一化（全角→半角、压缩空白、英文小写）后做子串比对，对不上就丢弃 |
| `kind` 白名单 | `person / org / place / concept / event / other`，未知一律归到 `other` |
| 自环丢弃 | `from == to` 直接扔 |
| 关系两端必须都是本批已确认实体 | 避免模型拿没出现的名字编关系 |
| 证据优先取原文 | 模型给的 `evidence` 也必须是原文子串；否则退化为「同时包含两端的原句」；再找不到就留空 |
| 自环 / 去重 / 上限 | 每批最多 40 实体、60 关系 |
| 分批 | 按块累积到约 6000 字符一批（不拆块），长笔记多次调用 |
| 串行 + 限流 | 令牌桶 9 请求/分钟（与转写共用 `rate_limit.rs`），429 退避 15s×n，其它错误 2s×n，确定性 4xx 不重试 |

## 图谱页（2D 力导 + 3D 星球）

视图有两种，工具栏右上角「力导图 / 3D 星球」切换（选择存 localStorage，下次打开还停在原视图）：

### 2D 力导图（G6 5.1.1）

- 布局：内置 `d3-force`（`preventOverlap` + 撞力），交互行为 `drag-canvas / zoom-canvas /
  drag-element-force / click-select`；G6 按需引入，图谱视图是**路由级懒加载**（不进首屏包）。
- 视觉编码：**节点大小 = 度数**、**颜色 = 类型**（人物 / 组织产品 / 地点 / 概念 / 事件 / 其它）、
  **边宽 = 强度（出现次数）**，强度 > 1 时边上标数字。
- 筛选（纯前端，不动数据）：类型多选、实体名关键词、最小度数 → 边只保留两端都在的。
- 详情面板：邻居（带方向与关系短语，可继续点下去）、出处笔记（可跳转到笔记、可单独重抽）、
  出处片段（点击打开笔记对应行）。
- 图上限：默认取度数最高的 **1500** 个实体（`graph_snapshot` 的 `limit`），
  被截断的数量会提示；筛选只作用于已取回的这部分。

### 3D 星球（three.js + 3d-force-graph）

- **独立懒加载**：只有切到 3D 才下载 3D 引擎（约 370 KB gzip），2D/首屏不受影响；
- 交互：自动缓慢旋转（右上角可暂停）、拖拽旋转 / 滚轮缩放 / 单击实体 → 右侧详情面板、
  悬停高亮邻居（其余变淡）、节点大小 = 度数、颜色 = 类型（与 2D 同一套）；
- 与 2D 共享同一份筛选数据（类型 / 关键词 / 最小度数），切换视图或筛选变化即时同步；
- 主题（浅色/深色）切换会重绘背景与配色；无 WebGL 的环境（少数旧 WebView）显示提示并让回 2D；
- 节点数超过 800 会提示低端设备可能卡顿——3D 适合「看全局」，日常查关系用 2D 更顺手。

## 检索增强（图谱邻居扩展）

在混合检索里做第三路召回，只在正文/向量召回之后、重排之前插入：

1. 取 RRF 后的候选片段（`candidate_k`）→ 查它们的实体（`chunk_entities`）；
2. 用**共享实体**找回其它片段：打分 = `Σ 共享实体数 / 该实体出现的块数`，
   即**稀有实体权重更高**，避免「会议」「项目」这类高频实体把整库拉进来；
3. 这部分作为第三路（权重 `GRAPH_WEIGHT = 0.5`）并入 RRF，再统一走重排与截断
   → **只增不减**召回，重排仍会按相关性把关；
4. 结果行会标注来源 `graph`，`RetrievalTrace` 里带：

| 字段 | 含义 |
| --- | --- |
| `graphEntities` | 命中片段涉及多少个实体（0 = 图谱没参与） |
| `graphHits` | 邻居扩展召回了多少条候选 |
| `graphAdded` | 最终结果里有几段来自图谱扩展 |
| `mode` | 基础模式 + 后缀 `+graph`（如 `hybrid+rerank+graph`） |

开关：`RetrieveOptions.expand_entities`（默认开）、`expand_k`（默认 4 条候选）。
**图谱为空时静默不生效**，不报错、不降级提示（图谱本来就是可选能力）。

## 排障

| 现象 | 原因 / 处理 |
| --- | --- |
| 抽取报「未配置对话模型」 | 到「设置」里填对话端点（图谱抽取只用对话模型，与 embedding 无关） |
| 日志里大量「限流等待 Ns」 | 正常：上游 9 请求/分钟，长笔记会排队；嫌慢可以在图省事的时候少抽几篇 |
| 抽出来的实体很少 | 笔记太短、或模型没按 JSON 输出（看横幅里的错误）。可在「设置」里换模型后「全量重抽」 |
| 图谱页一片空白 | ① 还没抽取；② 筛选条件太严（点「清空筛选」）；③ 图上限截断（看提示） |
| 名字相近的两个节点 | V1 **不做同义归并**：「Milvus 向量库」与「Milvus」会是两个节点，靠关系连起来看 |
| 问答没有出现「图谱补 N 段」 | 命中片段没有实体（没抽过/笔记太新），或扩展候选被重排按相关性丢掉了 |

## 实测记录（2026-09-22，真网关 Qwen-Inno-35B-v1）

- 2 篇中文笔记（周会 + 部署记录）增量抽取：**20.1s**，22 实体 / 14 关系，跨笔记实体 4 个
  （王强、李娜、gpu-node2、new-api 网关），全部实体名都能在原文里找到；
  再抽一次 **0 请求**（增量跳过）。
- 邻居扩展：库里 3 篇笔记，查询「镜像拉取超时」在**关闭向量与重排**时只命中 1 篇，
  图谱把共享实体（张伟）的另 2 篇补回，`mode=fts+graph`、`graphAdded=2`。
- 完整链路（向量 + 重排 + 图谱）trace 正常，问答 800~1600ms。
